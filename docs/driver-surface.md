# Driver surface of kode-sdk (commit c9568a3) for dotbench

Machine-readable companion: `driver-surface.json`. Generated by scripts from the headers, implementation files and call sites; the SDK was only read, never built or modified.

## How this was measured

- Scanned 155 upper-layer .c files (kode, kode_sys, kaos, kqp, kscreen, kode_screen, klog) for calls or function-pointer references to anything declared in the khal/kdrv headers (743 declared names). Result: **543 functions** (537 called + 6 referenced as pointers).
- Prototypes are copied from the headers; all 543 have a header doc, a definition and an implementation file.
- Honest limit: classification is by header docs, the includes and transitive dependency closure of each implementation, membership in the SDK host suite (215 SOURCES_UNDER_TEST) and targeted reads. **Not every implementation body was read line by line.** Per-file judgements (59 impl files) are in the `why` field of each function.

## Will bite

1. **FreeRTOS and QP port shim fidelity.** qpc includes the whole FreeRTOS API (qp_port.h:74-76); qf_port.c uses xTaskCreateStatic, xQueueCreateStatic, xQueueSendToBackFromISR and portMUX critical sections. klog.c:133-134 calls xPortCanYield and xTaskGetSchedulerState to decide whether it may lock. The shim must model ISR-versus-task context, or khal_sem_signal/kqp_post_from_isr take the wrong path.
2. **ISR-context callbacks.** kdrv_buttons_top_attach (buttons_ao.c:762, posts via kqp_post_from_isr), kdrv_tca6408a_int_attach (ioexp_ao.c:288), khal_exp_irq_attach (kode_sys_exp.c:98, kode_standard_ao.c:933/996) and khal_sem_signal from the DSI completion run in interrupt context: they may only post static events. In the browser, fire them from a dedicated context, never from a JS callback that blocks. kdrv_ir_init callbacks arrive on the esp-hosted thread; BLE callbacks on the NimBLE host task.
3. **Timing: 1 kHz tick and flush completion.** kqp_tick.c:34 starts khal_timer_periodic(1000 us). A fake kdrv_display_flush_wait that never signals hangs kscreen (it drops the frame on timeout) and display_ao. Blocking calls (radio_run, net_run, es8311_run, rfid_lf_run) only run on worker tasks; HTTP via fetch needs an Atomics.wait bridge.
4. **Persistence.** NVS (khal_nvs_*) and wall clock (kdrv_clocks_wall_keep/restore via NVS), khal_power_off_note (survives deep sleep), kdrv_slot_crashes/kdrv_display_recoveries (LP registers), apps partition 0xC40000 (0xBC0000 B), app_pending 0x1A00000 (6 MB), storage FAT 2 MB, khal_keep 1 MiB. khal_nvs_* returns KODE_DENIED from a PSRAM-stack task: drop that check in the fake.
5. **Large and aligned buffers.** khal_alloc_psram(align,size) is called with alignments up to 64 and must return zeroed memory. Panel 410x502 RGB565, stride 820 B, 411640 B per frame. KODE_SYS_FILE_READ_MAX 32768, KODE_HTTP_BODY_MAX 65536, KCHAN_OUT_BYTES / NET_STREAM_CHUNK / STORAGE_CHUNK 32 KiB, KAPP_ICON_BYTES 49152, KQP_AO_STACK_BYTES 8192, IR symbols 256 each way.
6. **Host fakes are not drop-in.** fake_khal_sync (locks lock nothing), fake_khal_worker (no task) and fake_khal_time (manual clock) assume one thread. tests/host/mocks/* are CMock expectation mocks, not behavioural models. fake_khal_system.c has an unconditional esp_image_verify stub.
7. **sdkconfig.h and build gating.** 55 upper-layer files include sdkconfig.h and use about 50 distinct CONFIG_KODEOS_* symbols; the wasm build must generate it. kdrv/CMakeLists.txt gates kdrv_radio/c5/c5svc/frames on CONFIG_KODEOS_RADIO, kdrv_wifi on WIFI, kdrv_net on RADIO && WIFI && NET, kdrv_ble* on BLE; kdrv_c5_hold.c is built only with RADIO=n. khal_system_esp.c #errors without the board memory policy, khal_sync_esp.c without picolibc (and needs <envlock.h>).
8. **Audio cannot sit under khal_i2c.** kdrv_es8311_init hands khal_i2c_bus() (a raw IDF bus handle) to esp_codec_dev. Fake at the kdrv_es8311 API.
9. **Radio is reached through dispatchers.** Upper layers do not call kdrv_wifi_connect/scan/start, kdrv_ble_start/scan/advertise or most kdrv_net_mqtt_* directly: they use kdrv_radio_run (radio_run_wifi/radio_run_ble) and kdrv_net_run. Replace kdrv_radio.c by a copy of the dispatch switch. IR lives on the C5, so every call is a request/reply over kdrv_radio_peer_* (500 ms wait).
10. **Weak symbols and LVGL.** KAOS_WEAK (`__attribute__((weak))`) appears about 104 times in 14 files for neighbour AO references: verify weak-undefined behaviour under wasm-ld. kscreen.h:15 includes lvgl.h, lv_init/lv_tick_set_cb at kscreen.c:432-433, LV_OS_FREERTOS=y. khal_task_psram.h is force-included for kui (kui/CMakeLists.txt:179-197): skip it.
11. **Factory-only code.** kdrv_ov5640, kdrv_pcf8574, kdrv_ads1115, kdrv_dock_loop and kdrv_station need CONFIG_KODE_TEST_DOT: ignore (camera 6 + other 4 functions).
