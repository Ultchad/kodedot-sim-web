## What exists

- `runtime/rtos` FreeRTOS/ESP-IDF-flavoured layer on pthreads (85 unit checks, `runtime/rtos/test/run.sh`); see its README for the deliberate differences.
- `runtime/idf` esp_err, esp_log (default sink: bridge LOG channel; `esp_log_set_vprintf` honoured), esp_timer (service thread, once/periodic/skip_unhandled_events), esp_rom (printf, delay, crc8/16/32), heap_caps, esp_random, esp_system, esp_app_desc_t (256 bytes, for kapp_desc.c's asserts), `soc/` LP store registers backed by RAM, an `envlock.h` stand-in. `sdkconfig.h` is generated by `tools/gen_sdkconfig.py` from the SDK's and LVGL's Kconfig plus `runtime/idf/sdkconfig.web.defaults`.
- `runtime/bridge` the shared state (see its README).
- `runtime/drivers/<area>/` (each with an `area.json`, see Stage 1): `system`, `alloc`, `console`, `nvs`, `gpio` (virtual pin table + the TCA6408A model with the five expander buttons and TP_INT), `i2c` (bus over virtual chips), `led` (KTD2026), `touch` (CST820), `display` (flush/flip/backlight/dirty rows into the RGBA framebuffer), `time` (settimeofday), `sync` (nothing to add: the real SDK files run on the rtos layer).
- Generated stubs are written to `build/stubs/` by `tools/gen_stubs.py` (they depend on which symbols the compiled objects define); their support code is `runtime/bridge/stub_support.c`.
- `tools/dotbench` (`sdk`, `build`), `tools/gen_sdkconfig.py`, `tools/gen_stubs.py`, `tools/dblib/`.
- `tests/node/` harness, the two acceptance tests, `run.sh`.

## Seam decisions

- Seam for input and the LED is `khal_i2c` / `khal_gpio`, not the kdrv layer: `kdrv_buttons`, `kdrv_tca6408a`, `kdrv_led`, `kdrv_cst820` and the AOs above them (AO_IoExp, AO_Buttons, AO_LedMgr, AO_Touch) are the SDK's real code. The page's button/touch calls move virtual pins and chip registers; the real INT-line / debounce / polling logic runs.
- The TCA6408A model follows the datasheet: INT falls when an input differs from the last input-register read and rises on that read. GPIO interrupts follow the documented ESP-IDF contract (trigger disables, `khal_gpio_irq_enable` re-arms, a still-true level condition fires again).
- Seam for the display is `kdrv_display_*`: two RGB565 framebuffers with the real flip contract, converted to RGBA8888 into `kweb_state.fb` at flush; exactly one completion per flush for `kdrv_display_flush_wait` / `_abort` (risk 1 below).
- One FreeRTOS task = one pthread; a single global lock for critical sections; tick derived from the monotonic clock.

### Build-level shims

- Every SDK/LVGL file is compiled with `-include stdio.h` (`storage_ao.c` calls `snprintf` without including it; on IDF it arrives through an IDF header) and `-DESP_PLATFORM` (needed for LVGL's `lv_conf_kconfig.h` path), `-DKODE_SYS_INTERNAL_ALLOWED -DKODE_INTERNAL_ALLOWED`, `-w`.
- `kode_sdk_version.h` is generated into `build/` (the SDK writes it with CMake).
- The link uses `-Wl,--wrap=gettimeofday` so that `settimeofday` (absent in Emscripten's libc) has effect.
- `kui_pack.c` is not compiled: it needs cJSON, which could not be downloaded offline. Nothing the examples reference.
- `khal_alloc_psram` rounds the alignment up to 64 bytes and zeroes the block (callers expect cache-line alignment and zeroed memory).
- Heap figures (`khal_heap_free` etc.) are constants; `esp_log_level_*` are no-ops.

## Notes on the risks the coordinator flagged

1. **Flush-done**: handled. `kdrv_display_flush` completes synchronously and signals the single binary completion; `flush_wait(ms)` consumes it, `flush_abort` signals it. display_lvgl renders and the counter updates.
2. **1 kHz tick / ISR paths**: QF comes up at 1000 Hz (log line `kqp QF up: tick=1000Hz`). `xPortCanYield` is always true and the "ISR" callbacks (GPIO interrupt -> `QACTIVE_POST_FROM_ISR`) run on whichever thread triggers them, including the page's thread inside `kweb_button`; verified by the tests (press -> LED toggles).
3. **`#error` guards / CONFIG_KODEOS_***: `khal_system_esp.c` is replaced so its `#error` is not reached; `khal_sync_esp.c` compiles unchanged. All CONFIG values come from the generated `sdkconfig.h` (800 symbols, 232 enabled). The kdrv headers are preprocessed against that config by the stub generator, so stubs match the enabled declarations.
4. **Host-test fakes**: not used.
5. **KAOS_WEAK under wasm-ld**: works. Undefined weak references (`kaos_radio_start`, `kaos_ir_start`, `kode_file_state_free`, ...) resolve to null, no archive member is pulled for them, and the apps boot (RADIO=n).
6. **PSRAM-style allocations**: 64-byte aligned and zeroed, see above.

## Stage 1 (areas, restart, browser)

Delivered: parallel-safe areas, firmware restart/reset, the browser adapter, the area guide.

- **Areas**: `runtime/drivers/<area>/area.json` (manifest: supersedes, sources, i2c_chips, exports, sdkconfig, js,
  test_apps), discovered by globbing; chip registration is generated into `build/gen/areas_gen.c`; the stubs are
  generated into `build/stubs` (the checked-in `runtime/drivers/_stubs` is gone). The old `REPLACED` table and
  `exports.txt` files are gone, replaced by the manifests. `tests/node/run.sh [--rebuild] [area...]`.
  Builds are relocatable (content hashes over normalised paths); `dotbench seed OLD_BUILD` copies a build dir.
  Two concurrent builds in different `--build` dirs were run: the third dir was untouched. See `docs/DRIVER-AREA-GUIDE.md`.
- **Restart**: `kweb_restart(reason, target)` (khal_restart, esp_restart, panic, failed ESP_ERROR_CHECK) records the
  reason, bumps `restart_seq`, wakes the page and parks the thread; the host terminates all workers and boots again
  (`noInitialRun`, boot block and persistent regions written, `callMain`). Implemented `khal_keep_*`,
  `kdrv_running_desc` (from app.json), `kdrv_reset_reason`, RFID/codec park. "keep" (1 MiB) is cleared at power-on,
  "nvs" (128 KiB arena) persists. Test app: `runtime/drivers/system/testapp` (reset_probe).
- **Inputs** are lock-free: `kweb_button`/`kweb_touch` push to a 256-entry SPSC ring; a pump pthread applies them.
- **Browser**: `runtime/web-adapter/` (README), `tests/browser/run.sh` (headless Chrome, COOP/COEP/CSP server).
- Deviations: (1) the worker URL inside the Emscripten main script (`new URL("x.js", import.meta.url)`) is
  patched in the main-thread blob only, because that expression fails under a blob URL; workers get the unmodified
  script. (2) Blob URLs are revoked 10 s after a package is replaced (revoking at once made terminated pool workers
  report load errors). (3) `kweb_time_offset_ms`/`kweb_time_set_offset_ms` added so the RTC offset survives restarts.
  (4) The rtos `test_notify` timing gaps were widened (flaked under load).
- Known residual: under Node, RSS grows ~3 MB per restart (the old shared memories are not returned until the
  process exits); the Node test tolerates +80 MB over 16 restarts. In Chrome the JS heap and wasm memory (96 MiB) stay flat
  over 5 restarts. Worker count and thread count are flat in both.
- Not built: IndexedDB mirroring of the persistent regions (adapter exposes `exportPersist/importPersist`); Firefox
  has no `Atomics.waitAsync` (polling only).

## Notes for the next stage

- Console input path is `kweb_console_input(ptr, len)`; output is the CONSOLE text channel. The firmware echoes typed

- Browsers need cross-origin isolation (README of the adapter lists the headers and CSP).
